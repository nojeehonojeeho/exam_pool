# 수학 문제·해설 HWP 미주작업 지시서

공통 실행 기본값은 [사용자 의도 기반 실행 기본값](USER_INTENT_EXECUTION_DEFAULT.md)을
적용한다. 미주 요청은 내부 체크포인트를 거쳐 실제 연결·재열림·검증까지 실행한다.

최신 선행 체크포인트·내용 보존·최종 출고 규칙은
[원문 충실도 v2](PDF_HWP_SOURCE_FIDELITY_V2_WORK_INSTRUCTIONS.md)를 함께 적용한다.
문서 반영과 실제 코드 연동·제작 검증은 별도이며, 미주 개수만으로 PASS하지 않는다.

## 1. 적용 시점

이 문서는 사용자가 미주 삽입을 요청한 경우에만 적용한다. 변환과 미주를 한 번에
요청할 수 있으며 같은 요청에 대해 다시 제작 승인을 요구할 필요는 없다. 내부적으로
문제·해설 HWP/HWPX의 원문 충실도·편집성·배치 체크포인트를 먼저 검증하고 hash로
고정한 뒤 실제 미주를 삽입한다. 별도 미주 스타일이 없으면 검증된 기본 프로필을
사용한다. 문제 전용 요청에는 해설이나 미주를 추가하지 않는다.

## 2. 입력과 결과물

- 입력: 동일 시험의 독립 문제본과 독립 해설본, 문항 번호 매핑표, 교사 피드백.
- 결과: (1) 문제-only 원본, (2) 해설-only 원본, (3) 미주 병합본, (4) 미주 QA 보고서. 원본 파일은 덮어쓰지 않는다.
- 미주 병합본의 본문 문제·수식·그림은 기존 편집 가능 구조를 유지한다. PDF 캡처를 본문 전체에 덧씌우는 방식은 금지한다.

## 3. 미주 삽입 규칙

- 각 미주는 인쇄된 문제 번호의 텍스트 런에 실제 HWP 미주 앵커로 연결한다. 번호 뒤에 일반 본문이나 떠 있는 그림을 붙여 미주처럼 보이게 만드는 방식은 사용하지 않는다.
- 문항 하나당 미주 하나로 stable item ID와 1:1 대응한다. 반복 인쇄 번호는 책·단원·세트·
  출현 구분과 문제/해설 내용을 함께 확인한다. 소문항·보기 숫자를 별도 미주로 만들지 않는다.
- 미주 본문은 검수된 해설본의 해당 문항을 그대로 옮긴다. 식·부호·답을 추론하여
  바꾸지 않는다. 해설 OCR 미확정 항목은 검수 원장에 위치와 원인을 기록하고 미주
  삽입을 차단한다. 대조 필요 표식을 미주 내용의 대체물로 넣지 않는다.
- 미주 삽입 후에도 선택된 layout mode의 단·보기·그림 상대 순서를 유지한다. 모든 문서에
  2단을 강제하지 않는다. 전후 문제 내용과 해설 미주 내용을 독립 snapshot으로 대조한다.

### 3.1 통합본의 본문 선행·문서 끝 미주 계약

통합본은 주 본문에 문제 1번부터 마지막 문항까지를 원본 순서로 먼저 배치하고,
그 뒤 문서 끝에 정답·해설 미주만 렌더하는 구조여야 한다. 주 본문에 해설 제목,
정답·풀이 문단, 해설 그림을 복제하거나 독립 해설본을 단순히 이어 붙이지 않는다.
문항마다 native endnote reference 하나를 해당 문제에 연결하고, 미주 body는 그
문항의 정답·해설만 같은 순서로 보존한다.

저장 HWPX에서는 모든 `hp:endNotePr/hp:placement/@place`를
`END_OF_DOCUMENT`로 명시한다. `footNotePr`의 `EACH_COLUMN`은 각주 설정이므로
미주 위치를 판정하는 값으로 사용하지 않는다. `endNotePr` 누락·빈 placement·
`EACH_COLUMN`/`EACH_PAGE` 등 문서 끝 이외의 값은 각각
`ENDNOTE_PLACEMENT_UNDECLARED` 또는 `ENDNOTE_PLACEMENT_INVALID`로 자동 FAIL한다.
한글 재열림·렌더에서 마지막 문제 뒤에 미주 영역만 이어지는지, 문제 하나를
복사·이동할 때 native 연결이 따라오는지를 확인한 뒤에 출고한다. 이 계약은
확률과 통계·수학 II·고등수학(상)·고등수학(하)을 포함한 모든 과목과 이후 작업에
동일하게 적용한다.

## 4. 문항 매핑·검수

1. `MATH_PDF_CONTENT_SCOPE_AND_ENDNOTE_MAPPING.md`의 검수된 scope manifest에서
   문항 ID와 문제/해설 영역을 가져온다. 페이지 번호만으로 ID를 만들지 않는다.
2. 모든 ID가 정확히 한 번씩 매핑되는지, 누락·중복·교차 매핑이 없는지 검사한다.
3. HWP/HWPX를 다시 열어 미주 개수와 자동번호 범위를 확인한다. 미주 번호가 본문 번호 순서와 어긋나거나 빈 미주가 있으면 실패다.
4. 문제 번호를 클릭/선택했을 때 해당 해설 미주로 이동하는지 한글에서 확인한다.
5. 전체 PDF 렌더링과 문항별 확대 검수로 미주가 본문을 가리거나 열·페이지 밖으로 떠나지 않는지 확인한다.

한 PDF 페이지에 문제 둘이 있으면 미주도 둘이어야 한다. 한 해설이 여러 페이지에
걸치면 같은 item ID의 연속 영역으로 합치되 미주는 하나다. `page_round_robin`, modulo,
페이지당 미주 하나, 인쇄 번호만 사용한 대응은 자동 FAIL이다.

## 5. 수식·그림·이미지 주의사항

- 해설의 모든 수식은 실제 네이티브 수식이어야 한다. 평문·이미지 대체는 FAIL이다.
  순수 그래프·기하·삽화 crop만 예외 감사하고 문항 번호·문장·답·표를 그림으로 대체하지 않는다.
- 이미지 전용 fallback 문항은 미주 삽입을 차단하고 편집형으로 복원·검수한다.
  원문과 편집성이 확인되지 않은 상태에서 “무오류” 또는 “완료”로 표시하지 않는다.
- 미주 삽입 후에도 문제 번호·그림·보기 상자가 동일한 문제 셀에 남아 있는지 확인한다. 그림이 상단이나 다음 문항으로 이동하면 미주 삽입을 중단하고 레이아웃을 복구한다.

## 6. 완료 기준

미주 병합본은 다음을 모두 통과해야 제공한다.

- 문제·해설 문항 ID 1:1 매핑, 누락·중복 없음
- HWP와 HWPX 재개방 성공, 미주/자동번호 수 일치
- 문제 번호 순서와 미주 앵커 순서 일치
- 선택된 배치 계약의 단·보기·그림 배치 및 페이지 흐름
- 정답·모든 해설 문단·수식·숫자·부호·표·그림·주석의 원문 대조, 미확정/누락/혼입/중복 0
- 실제 텍스트·수식 편집 시험, HWP/HWPX 재열림 및 검사용 사본의 문항 복사·이동 미주 추적
- 원문/체크포인트/미주 출력/출고 파일의 내용·해시 연결과 전체 문항별 검수 범위 기록
- 미주가 없는 문제-only·해설-only 원본과 별도 병합본 보존

## 7. 최신 4종 재감사 추가 게이트

7월 더프·4월 종로·4월 대성 더프·5월 더프 재감사는
`docs/DUFF_NATIVE_ENDNOTE_STRICT_REAUDIT_4FILE.md`의 fail-closed 절차를 따른다.
수식 글꼴만 바꾼 HWPX, 미주 개수만 맞춘 결과, 레거시 미주 계약 manifest는
최종 PASS로 인정하지 않는다.

- 문제·해설 PDF별 `math-source-manifest-v1`을 먼저 검증한다.
- 검수 PDF occurrence → MathIR root → writer → HWPX `hp:equation` → HWP COM/재열림
  `eqed`의 개수·순서·소유권을 연결하고 재출력 PDF에서 같은 occurrence의 내용을 시각 대조한다.
- `HYhwpEQ`, 11pt, `baseUnit=1100`, 비어 있지 않은 script가 전수 일치해야 한다.
- 해설 본문·정답·수식·표를 이미지로 대체한 미주는 자동 FAIL한다.
- HWP/HWPX 재열기와 EquationModify, 문항 복사·이동 미주 추적을 확인한다.
- 네 시험 중 하나라도 실패하면 집계 결과는 `4/4 PASS`로 표시하지 않는다.

저장소의 `app/duff_native_endnote_strict_qa.py`와
`tools/duff_native_endnote_strict_qa.py`는 외부 JSON spec을 받아 네 시험을
집계하며, PDF·HWP/HWPX·전사 내용은 저장소에 포함하지 않는다.
