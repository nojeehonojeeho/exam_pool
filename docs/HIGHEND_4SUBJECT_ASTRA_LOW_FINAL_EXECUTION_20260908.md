새 실행 폴더에 변경·증거를 기록한다. 전체를 옛 OCR 빌더로 다시 만드는 대신 확인된

## 제작과 출고

문제/해설 단독본과 네이티브 미주 통합본은 같은 내용 개정판에서 만든다.
실제 텍스트·수식·표 편집성, 미주 참조/본문 대응, 복사·이동을 검사한다.
COM은 직렬 실행한다. RegisterModule 실제 True, 승인창 열거 성공, 승인창 0회,
저장·닫기·재열림·PDF 출력과 최초/재열림 소유 PID 종료를 모두 확인한다.
열거 실패는 0회가 아니며 skip-com/XML-only는 COM PASS가 아니다.
기존 사용자 프로세스를 이름으로 일괄 종료하지 않는다.

최종 출력 전 페이지를 300dpi 이상 같은 물리 배율로 검사한다. 잘림·겹침·단 침범·
소유 문항 분리·문단 밀착·순서 역전·비정상 공백을 확인한다. 원문의 의도된 작업 공간은
결함으로 삭제하지 않는다. 대표 이미지/contact sheet는 전수 검수의 대체물이 아니다.

설정의 모든 required_gates와 zero_required를 실제 파일에 결합된 증거로 충족하고,
candidate 수와 evidence closed 수가 같아야 FINAL_PASS다. 빈 범위, 선언 불일치,
중복/미확정 ID, 미소비/알 수 없는 필드도 차단한다. 문서·정책 테스트 통과는 제작
통과가 아니다. 기존 출고 게이트를 우회하거나 상태 JSON을 수동 승격하지 않는다.

수정 후 영향 범위와 회귀를 재검증한다. 원본 접근 불가·권한 부재·복구 불가능한 손상은
HARD_BLOCKER로 기록하되 독립적으로 가능한 나머지 작업은 계속한다.

최종 제공: 과목별 문제·풀이·미주 HWP/HWPX, 검수 PDF, 범위/원본/MathIR/미주/COM/
시각 증거, 수정 전후 대표 이미지, 회귀 결과, 변경 파일·출력 경로·커밋·원격 링크.

# 실제 시험에서 확인한 보완 사항 (2026-09-08)

아래는 단일 문항 시험에서 확인한 실행 개선이며 전체 교재의 FINAL 증거가 아니다.

- 해설 설명문 → 독립 수식 → 원문 보충 설명은 `app.hwp_solution_flow.bind_solution_flow`로 명시적으로 연결한다. `keep_with_next`와 `keep_lines`는 boolean만 허용한다. 문자열 `"false"`를 True로 해석하지 않는다. OCR 줄마다 새 문단을 만드는 방식은 금지한다.
- 실제 로컬 writer는 독립 수식에도 `keep_with_next`를 적용해야 한다. 제목 삽입 함수가 이미 문단을 종료한다면 호출자가 빈 문단을 중복 삽입하지 않는다. `tools/highend_writer_flow_patch.py <실제 writer 경로>`로 두 변경의 적용 상태를 검사한다. `--apply`는 알려진 구조에만 백업 후 기계적으로 적용하며 알 수 없는 구조는 중단한다.
- 끝의 빈 페이지는 원문 내용 삭제나 글자 축소로 없애지 않는다. 작성기가 추가한 말미 빈 문단임을 위치와 원장으로 확인한 경우에만 제거하고, 저장된 텍스트·수식·표 셀 순서의 전후 동일성을 검사한다. 이 조치는 일반 빈 문단 일괄 삭제 허가가 아니다.
- 미주 전 문제·해설과 미주 후 본문·미주 본문을 각각 같은 개정판의 구조 스냅샷과 비교한다. 대응 본문과 수식 순서가 일치해야 하며 단순 개수 일치로 대체하지 않는다.
- 표 안 문항의 복사/이동 시험에서 `MoveDocEnd`는 내부 리스트 끝일 수 있다. 본문 붙여넣기는 `MoveTopLevelEnd` 이후 실제 `get_pos()[0] == 0`을 확인한다. 원본은 저장하지 않고 별도 시험 산출물을 사용한다.
- 실제 Copy/Cut/Paste 반환값, 선택 시작·끝·붙여넣기 위치를 기록한다. 오류 후 파일이 저장됐다면 같은 전사를 반복하지 말고 해당 저장 파일의 재열림 검증부터 재개할 수 있다.
- 문서를 비운 직후 `quit`이 RPC busy를 반환하는 경우 `app.hwp_owned_quit.quit_owned`는 소유 HWND/PID가 맞고 모든 문서 경로가 비어 있을 때만 정상 `Quit`을 한 번 더 호출한다. 프로세스 강제 종료·사용자 문서 저장·전역 메시지 차단은 하지 않는다. 외부 호출 시간제한과 종료 PID 확인은 별도로 유지한다.
- 승인창 조회 실패, 등록 False, 이전 세션 미종료는 새 COM 생성을 차단한다. 소스 검수는 계속할 수 있다. 단일 문항 복사·이동 PASS를 전체 교재 PASS로 승격하지 않는다.

관련 합성 테스트: `test_hwp_solution_flow.py`, `test_highend_writer_flow_patch.py`, `test_hwp_owned_quit.py`, `test_hwp_com_security_serial_probe.py`.

## 문장 안 참조 표시와 경우 제목

- 검수 원문에 존재하는 참조 표시만 `metadata.unbreakable_phrases`에 명시한다. `app.hwp_protected_text`는 해당 구문 안의 공백만 실제 `InsertNonBreakingSpace`로 삽입한다. 원문 문장이나 숫자·수식은 다시 쓰지 않는다. `tools/highend_writer_protected_text_patch.py <writer>`로 실제 경로의 적용 상태를 확인한다.
- 저장 HWPX의 `nbSpace`는 일반 공백과 다른 제어로 보존·검사한다. 모든 공백을 삭제하거나 일괄 정규화하여 불일치를 숨기지 않는다. 허용된 표시 외 공백·문단·수식 경계는 정확히 비교한다. 미주 전후에도 같은 보호 구문 계약을 적용한다.
- 원문에서 확인한 경우 구분 제목은 `role=case_heading`과 `keep_with_next=true`로 다음 설명과 묶는다. 일반 문장을 제목으로 추측하지 않으며, 제목만 페이지 아래에 남는지 미주 렌더에서도 검사한다.
- 종료 실패는 예외의 실제 HRESULT와 EXCEPINFO를 기록한다. RPC busy와 `RPC_E_SERVERFAULT`를 혼동하지 않는다. 후자는 정상 종료 중 실제 관찰된 코드 `-2147417851`이다. 소유 PID/빈 문서 상태 확인 뒤 정상 Quit을 한 번 더 요청하는 것 외에 자동 강제 종료는 하지 않는다. 재열림 실패 전 저장된 파일은 보존하고 재열림부터 이어갈 수 있다.
- 복사·이동 검사에서도 문항 COM 컨트롤 참조를 종료 전에 해제한다. 일반 텍스트뿐 아니라 본문 수식, 그림 리소스, 미주 본문, 자동 번호, COM 수식 순서를 함께 비교한다.

## 원문 빈칸 기호

- 원문의 자리 표시용 빈 사각형도 누락하거나 일반 문자 fallback으로 우회하지 않는다. LaTeX `\square`는 명시적 symbol 노드와 HWP 수식 스크립트 `□`로 컴파일한다. 연속 사각형의 개수·순서도 보존한다.
- 컴파일 성공만으로 지원 완료로 판정하지 않는다. 실제 작성 경로에서 HWP와 HWPX의 저장·재열림 수식 스크립트를 대조하고 렌더된 사각형이 보이는지 확인한다. 관련 합성 테스트는 `test_hwp_equation_compiler.py`에 있으며, 해당 기호와 무관한 기존 검수 내용은 변경 영향 범위를 구분해 재사용한다.

## 직렬 세션의 Python 래퍼 수명

- 설치된 pyhwpx의 `Hwp.__del__`이 `CoUninitialize()`를 호출하는 경우, 이전 래퍼가 새 세션 할당 도중 해제되지 않도록 한다. `app.hwp_session_references.HwpSessionReferences`로 문서 단위 직렬 작업의 래퍼를 유지하고, 소유 PID 종료를 독립 확인한 뒤에만 명시적으로 해제한다. 장시간 전체 교재의 모든 래퍼를 무제한 보관하는 방식은 아니다.
- 현재 실행의 합성 표 시험에서 첫 저장은 성공했지만 두 번째 세션 Open이 개체 연결 오류로 실패했다. 저장된 파일은 보존하고 별도 세션 재열림부터 성공시켰다. 래퍼 수명 유지 후 같은 직렬 시험과 미주 복사 시험은 성공했다. 이는 해당 실행 경로의 개선 증거이며 모든 COM 오류의 원인이 같다는 증거가 아니다.
- 실패한 세션은 기록된 PID·시작 시각·소유 관계와 문서 상태로 확인한다. 빈 합성 시험 문서만 정상 Quit 대상으로 삼았으며 사용자 문서 강제 종료·전역 설정 변경은 하지 않았다. 예외 후 새 파일을 무조건 다시 만드는 대신 저장 체크포인트를 재사용한다.

## 원본에서 확인한 표 병합

- 표의 병합을 추측하지 않는다. 검수 원장의 `metadata.cell_merges`는 0부터 시작하는 `[row, col, height, width]`로 명시한다. `app.hwp_table_merges`는 직사각형 셀 행렬, 범위·중복, 덮이는 셀의 빈 내용 여부를 먼저 검사한다. 내용이 있는 셀을 병합하여 잃거나, 지원되지 않은 병합을 평문·그림으로 우회하지 않는다.
- 현재 구현은 가로 또는 세로의 일직선 병합만 지원한다. 두 방향 동시 병합은 미지원으로 중단하고 추가 원본·합성 검증을 요구한다. 원장의 병합 좌표는 원문 표 셀 소유 관계와 함께 검수한다.
- 원문 표의 열 위치 번호는 명시적인 텍스트 세그먼트 `role=source_column_position_label`로 보존할 수 있다. 수식 셀은 별도 수식 occurrence로 작성하며, 숫자가 있다는 이유만으로 표 전체를 수식이나 이미지로 바꾸지 않는다.
- `tools/highend_writer_table_merges_patch.py <실제 writer>`로 적용 여부를 검사한다. 셀 내용을 먼저 작성한 후 아래·오른쪽 병합부터 실행하고, 실제 COM 동작 반환값이 True인지 확인한다. 알 수 없는 writer 구조는 자동 추정 패치를 금지한다.
- 합성 가로·세로 병합 표의 HWP/HWPX 저장, 실제 HWP 재열림, 셀 내용·rowSpan/colSpan 동일성, 300dpi 렌더와 소유 PID 종료가 확인되었다. 이 결과는 표 기능의 제한된 실행 증거이며 전체 교재의 내용·서식 FINAL 증거가 아니다.
# 추가 실제 제작 경로 점검: 표와 문장 경계

- 해설 문서의 용지 기준 쪽은 해설 PDF의 `source_solution_pages`에서 선택한다. 문제 PDF의 `source_page` 숫자를 해설 PDF에 그대로 적용하지 않는다. `app.hwp_source_page_reference.reference_page`로 역할·페이지 범위를 검증하고, 실제 참조 PDF와 물리적 쪽번호를 실행 증거에 기록한다. 여러 원본 쪽의 스캔 규격 편차는 별도로 측정하며, 한 기준 쪽의 크기만 맞았다는 이유로 전체 원본 기하 일치라고 보고하지 않는다.
- 설명에서 직접 참조한 그림은 `metadata.keep_with_previous=true`로 관계를 명시하고, 직전 설명 문단에 `keep_with_next`를 적용한다. 내용이나 그림 순서를 바꾸지 않는다. 실제 미주 출력에서도 설명과 그림이 서로 다른 페이지로 분리되지 않았는지 다시 확인한다.

- 미주 복사·이동 시험은 `Copy/Cut=True`만으로 붙여넣기 준비 완료를 추정하지 않는다. 작업 소유 문서에서 Copy/Cut 직전 클립보드 sequence를 기록하고, `app.hwp_native_clipboard.wait_native_payload`로 변경된 sequence와 비어 있지 않은 `Hwp Native` 데이터 준비를 확인한다. 기록은 크기와 SHA-256만 보존한다. 다른 앱의 클립보드 내용을 출력하거나 수정하지 않는다.
- 준비 확인은 기본 5초, 최대 10초의 제한된 polling으로 수행하며, Windows delayed-render 호출 자체에는 별도 외부 worker watchdog을 유지한다. 준비 실패는 Paste 전에 실패 처리한다. 재시험 성공만으로 첫 실패 원인을 확정하거나 미주 전체 검수 PASS를 선언하지 않는다. 저장된 복사·이동 파일의 미주 내용·번호·수식 순서와 원본 불변성, PID 종료 검사는 그대로 유지한다.

- 표 셀에도 해당 블록의 명시적인 `unbreakable_phrases`를 전달한다. 본문에만 적용하고 표의 보충 설명 표시는 누락하지 않는다. 원본에 없는 공백을 임의로 추가하거나 모든 공백을 일괄 변환하지 않는다.
- 수식 목록 전후의 서술부와 조사는 한 원문 문장인지 대조한다. `의 …이다` 등 문장 끝 조각이 OCR 행 또는 수식 블록 경계 때문에 독립 문단이 된 경우, 원본에서 확인한 범위만 하나의 네이티브 문단으로 복원한다. 수식 occurrence ID와 순서, 원래 source block ID 연결을 유지한다.
- 정적 수식 증거 PASS 이후에도 실제 출력에서 문장 분절을 발견할 수 있다. 이전 후보를 보존하고 새 내용 개정판으로 수정한 뒤 저장·재열림·시각 대조를 다시 수행한다. 정적 검사를 전체 출고 PASS로 승격하지 않는다.

## 묶음 출력의 수식 인접 문자와 미주 참조 표시

- 개별 문항뿐 아니라 묶음의 실제 렌더를 검사한다. 현재 1~6번 묶음의 300dpi 검토에서는 6번 제목의 기울임 수식 끝과 바로 뒤 조사가 접촉해 보이는 부분을 발견했다. 글꼴명·스크립트·개수 일치만으로 인접 문자의 가독성을 입증하지 않는다.
- 한글에서 같은 스크립트로 EquationModify를 수행하는 별도 시험은 원문 내용 변경이 아니지만, 모든 간격 오류의 해결책으로 간주하지 않는다. 최초 파일을 보존하고 변경된 개체 크기·글꼴·실제 렌더를 비교한다.
- `app.hwpx_reviewed_layout`는 입력 SHA-256과 명시적 수식 인덱스·예상 스크립트·기존 여백을 모두 확인한 보정 계획만 받아 별도 파일로 출력한다. 수식 스크립트나 텍스트 공백을 수정하지 않으며, 기존 파일 덮어쓰기를 거부한다. 현재 시험의 오른쪽 바깥 여백 142 HWPUNIT(약 0.501mm)은 가독성 보정 설계값이지 원본에서 추출한 값이 아니다. 전 수식 기본값으로 자동 확대 적용하지 않는다.
- 문항 번호와 네이티브 미주 참조 번호를 삭제·평문화하여 겹침을 숨기지 않는다. 참조의 위첨자 표시 등 문서 서식으로 구분하고, 실제 저장·재열림 후 번호·연결·본문 불변성과 화면을 확인한다. 미주 본문의 자동 번호를 임의의 텍스트로 대체하지 않는다.
- 보정 패키지는 항상 `LAYOUT_CHANGED_REQUIRES_COM_AND_VISUAL_QA`이며 FINAL이 아니다. HWP/HWPX 재열림, 전체 영향 페이지 시각검사, 독립 문제/해설과 미주 전후 내용 대조, 복사·이동 영향 검증이 끝난 범위만 체크포인트로 인정한다. 원본 스캔의 쪽별 크기 편차와 한글 PDF 출력 크기 반올림은 별도 수치로 보고한다.

관련 합성 테스트: `tests/test_hwpx_reviewed_layout.py`.

## 명시적 설명·수식 연속 문단의 페이지 보호

원문 대조에서 하나의 설명에 종속된 연속 문단임을 확인한 경우,
후속 블록의 `metadata.keep_with_previous=true`로 관계를 기록한다.
독립 수식뿐 아니라 인라인 수식을 담은 텍스트 문단도 포함한다.
공통 `bind_solution_flow`는 바로 앞 텍스트/독립 수식에 `keep_with_next=true`를 부여한다.
원문 문장·수식·블록 순서는 변경하지 않으며, “이고” 같은 어미만으로 자동 추정하지 않는다.
연속 관계를 과도하게 연결해 큰 공백을 만들지 않도록 실제 미주 출력에서 재검사한다.
이 보정의 합성 테스트 통과는 원문 충실도나 전체 출고 PASS가 아니다.

## 표 안 중복 빈 문단의 제한적 보정

이번 실행에서 긴 조건 상자 뒤의 빈 페이지를 실제로 확인한 경우,
원본·본문 크기는 보존하고 검토된 빈 문단만 해시 결합 계획으로 제거한다.
`cell_tails`는 정확한 끝 빈 문단 수, `cell_spacers`는 정확한 문단 인덱스와
기존 문단 모양 ID를 요구한다. 공백 문자나 미주·책갈피·수식 개체가 있으면
거부하며 기존 파일은 덮어쓰지 않는다. 보정 전후 내용 스냅샷, 새 HWP/HWPX의
실제 재열림, 출력 페이지와 소유 PID 종료까지 검사한다.
이는 표 간격 보정이며 원본 수식 정확성이나 전체 FINAL을 대신하지 않는다.
긴 등식 뒤 문장부호 고립은 명시적 표시 줄 계획으로 해결하고 실제 렌더로 확인한다.

## 긴 등식 표시 계획과 원문 보존

`hwp_equation_line_layout.wrap_equality_chain`의 원본 SHA-256·검토된 최상위 등호
순번을 사용한다. 원본 MathIR와 dialect는 보존하고 `eqalign` 표시 스크립트를 별도로
기록한다. 한 개 네이티브 수식 개체와 지정 글자 크기를 유지하며 항을 생략하지 않는다.
인접 쉼표를 마지막 수식 행으로 옮길 경우 기존 쉼표 한 개를 확인하고 정확히 이동한다.
원문 대조 시 정확한 표시 계획만 역대응하고 쉼표 경계까지 복원한다.
문제·독립 해설·미주가 같은 내용 개정판인지, HWP/HWPX 재열림과 미주 복사·이동 후에도
수식 소유·순서가 같은지 확인한다. 전체 문서 자동 적용 또는 전체 FINAL로 확대 보고하지 않는다.
