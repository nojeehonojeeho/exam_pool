## 실행 경계

이번 실행만 Astra Low, 표준 속도를 요청한다. 전역 모델 설정과 향후 기본값은
변경하지 않는다. 설정 파일은 요청 정책이며 실제 모델·추론 강도의 실행 증명이 아니다.
모델 자동 대체와 제작 편집용 하위 에이전트는 사용하지 않는다. 무거운 OCR·렌더·COM은
한 번에 하나만 실행하며 부하를 확인한다. 기존 v2와 과거 원장·QA는 불변 보존하고
새 실행 폴더에 변경·증거를 기록한다. 전체를 옛 OCR 빌더로 다시 만드는 대신 확인된
오류와 영향 범위를 교정한다. 안전한 작업은 중간 승인 없이 계속한다.

## 범위와 검수

확률과 통계, 수학 II, 고등수학(상), 고등수학(하)의 문제 영역과 대응 해설을 포함한다.
개념 전용 영역은 제외한다. candidate/declared/legacy reviewed/evidence closed/open을
분리한다. Step B 기본·-1 변형은 실제 원본에서 확인된 별도 ID·bbox·해설 대응을 갖는다.
과거 VERIFIED나 메타데이터 존재만으로 closure를 인정하지 않는다. 유효한 체크포인트를
찾아 원본·입력·코드·출력 해시와 변경 영향에 따라 재사용한다.

`pdf_hwp_scope_reconciliation`은 메타데이터 진단기다. 과거 VERIFIED 수만 legacy로
집계하고 CLOSED 메타데이터는 `source_evidence_claim_ids`로 보존한다. 이 모듈의
`closure_assessment=NOT_PERFORMED_BY_METADATA_RECONCILER`는 전체 증거를 감사했다는
뜻이 아니다. 반환되는 closed=0을 실제 과거 검수 성과가 전무하다는 주장으로 쓰지
않는다. 기존 체크포인트 증거를 별도 색인에서 찾아 실제 검수해야 한다. 이 진단기의
`final_eligible`은 항상 false이며 출고 판정은 실제 production evidence gate가 한다.

포함 영역 전체는 600dpi로 원문과 대조하고 불명확한 부분만 900dpi로 확인한다.
OCR은 후보다. 문항·조건·질문·선지·표·그림·숫자·정답·풀이와 읽기 순서를 보존한다.
수식이 있는 문항은 occurrence 소유권·순서와 source→MathIR→writer→HWPX→COM
구조를 비교한다. 개수 일치나 화면 유사도만으로 통과하지 않는다.

## 제작과 출고

문제/해설 단독본과 네이티브 미주 통합본은 같은 내용 개정판에서 만든다.
실제 텍스트·수식·표 편집성, 미주 참조/본문 대응, 복사·이동을 검사한다.
COM은 직렬 실행한다. RegisterModule 실제 True, 승인창 열거 성공, 승인창 0회,
저장·닫기·재열림·PDF 출력과 최초/재열림 소유 PID 종료를 모두 확인한다.
열거 실패는 0회가 아니며 skip-com/XML-only는 COM PASS가 아니다.
기존 사용자 프로세스를 이름으로 일괄 종료하지 않는다.

최종 출력 전 페이지를 300dpi 이상 같은 물리 배율로 검사한다. 잘림·겹침·단 침범·
소유 문항 분리·문단 밀착·순서 역전·비정상 공백을 확인한다. 원문의 의도된 작업 공간은
결함으로 삭제하지 않는다. 대표 이미지/contact sheet는 전수 검수의 대체물이 아니다.

설정의 모든 required_gates와 zero_required를 실제 파일에 결합된 증거로 충족하고,
candidate 수와 evidence closed 수가 같아야 FINAL_PASS다. 빈 범위, 선언 불일치,
중복/미확정 ID, 미소비/알 수 없는 필드도 차단한다. 문서·정책 테스트 통과는 제작
통과가 아니다. 기존 출고 게이트를 우회하거나 상태 JSON을 수동 승격하지 않는다.

수정 후 영향 범위와 회귀를 재검증한다. 원본 접근 불가·권한 부재·복구 불가능한 손상은
HARD_BLOCKER로 기록하되 독립적으로 가능한 나머지 작업은 계속한다.

최종 제공: 과목별 문제·풀이·미주 HWP/HWPX, 검수 PDF, 범위/원본/MathIR/미주/COM/
시각 증거, 수정 전후 대표 이미지, 회귀 결과, 변경 파일·출력 경로·커밋·원격 링크.
저작권 원본·전사·문서·crop은 Git에 넣지 않는다. 원격 403은 접근 가능한 fork로
처리하며 문서 제작의 원본 접근 실패와 혼동하지 않는다.
# 실제 시험에서 확인한 보완 사항 (2026-09-08)

아래는 단일 문항 시험에서 확인한 실행 개선이며 전체 교재의 FINAL 증거가 아니다.

- 해설 설명문 → 독립 수식 → 원문 보충 설명은 `app.hwp_solution_flow.bind_solution_flow`로 명시적으로 연결한다. `keep_with_next`와 `keep_lines`는 boolean만 허용한다. 문자열 `"false"`를 True로 해석하지 않는다. OCR 줄마다 새 문단을 만드는 방식은 금지한다.
- 실제 로컬 writer는 독립 수식에도 `keep_with_next`를 적용해야 한다. 제목 삽입 함수가 이미 문단을 종료한다면 호출자가 빈 문단을 중복 삽입하지 않는다. `tools/highend_writer_flow_patch.py <실제 writer 경로>`로 두 변경의 적용 상태를 검사한다. `--apply`는 알려진 구조에만 백업 후 기계적으로 적용하며 알 수 없는 구조는 중단한다.
- 끝의 빈 페이지는 원문 내용 삭제나 글자 축소로 없애지 않는다. 작성기가 추가한 말미 빈 문단임을 위치와 원장으로 확인한 경우에만 제거하고, 저장된 텍스트·수식·표 셀 순서의 전후 동일성을 검사한다. 이 조치는 일반 빈 문단 일괄 삭제 허가가 아니다.
- 미주 전 문제·해설과 미주 후 본문·미주 본문을 각각 같은 개정판의 구조 스냅샷과 비교한다. 대응 본문과 수식 순서가 일치해야 하며 단순 개수 일치로 대체하지 않는다.
- 표 안 문항의 복사/이동 시험에서 `MoveDocEnd`는 내부 리스트 끝일 수 있다. 본문 붙여넣기는 `MoveTopLevelEnd` 이후 실제 `get_pos()[0] == 0`을 확인한다. 원본은 저장하지 않고 별도 시험 산출물을 사용한다.
- 실제 Copy/Cut/Paste 반환값, 선택 시작·끝·붙여넣기 위치를 기록한다. 오류 후 파일이 저장됐다면 같은 전사를 반복하지 말고 해당 저장 파일의 재열림 검증부터 재개할 수 있다.
- 문서를 비운 직후 `quit`이 RPC busy를 반환하는 경우 `app.hwp_owned_quit.quit_owned`는 소유 HWND/PID가 맞고 모든 문서 경로가 비어 있을 때만 정상 `Quit`을 한 번 더 호출한다. 프로세스 강제 종료·사용자 문서 저장·전역 메시지 차단은 하지 않는다. 외부 호출 시간제한과 종료 PID 확인은 별도로 유지한다.
- 승인창 조회 실패, 등록 False, 이전 세션 미종료는 새 COM 생성을 차단한다. 소스 검수는 계속할 수 있다. 단일 문항 복사·이동 PASS를 전체 교재 PASS로 승격하지 않는다.

관련 합성 테스트: `test_hwp_solution_flow.py`, `test_highend_writer_flow_patch.py`, `test_hwp_owned_quit.py`, `test_hwp_com_security_serial_probe.py`.

## 문장 안 참조 표시와 경우 제목

- 검수 원문에 존재하는 참조 표시만 `metadata.unbreakable_phrases`에 명시한다. `app.hwp_protected_text`는 해당 구문 안의 공백만 실제 `InsertNonBreakingSpace`로 삽입한다. 원문 문장이나 숫자·수식은 다시 쓰지 않는다. `tools/highend_writer_protected_text_patch.py <writer>`로 실제 경로의 적용 상태를 확인한다.
- 저장 HWPX의 `nbSpace`는 일반 공백과 다른 제어로 보존·검사한다. 모든 공백을 삭제하거나 일괄 정규화하여 불일치를 숨기지 않는다. 허용된 표시 외 공백·문단·수식 경계는 정확히 비교한다. 미주 전후에도 같은 보호 구문 계약을 적용한다.
- 원문에서 확인한 경우 구분 제목은 `role=case_heading`과 `keep_with_next=true`로 다음 설명과 묶는다. 일반 문장을 제목으로 추측하지 않으며, 제목만 페이지 아래에 남는지 미주 렌더에서도 검사한다.
- 종료 실패는 예외의 실제 HRESULT와 EXCEPINFO를 기록한다. RPC busy와 `RPC_E_SERVERFAULT`를 혼동하지 않는다. 후자는 정상 종료 중 실제 관찰된 코드 `-2147417851`이다. 소유 PID/빈 문서 상태 확인 뒤 정상 Quit을 한 번 더 요청하는 것 외에 자동 강제 종료는 하지 않는다. 재열림 실패 전 저장된 파일은 보존하고 재열림부터 이어갈 수 있다.
- 복사·이동 검사에서도 문항 COM 컨트롤 참조를 종료 전에 해제한다. 일반 텍스트뿐 아니라 본문 수식, 그림 리소스, 미주 본문, 자동 번호, COM 수식 순서를 함께 비교한다.
